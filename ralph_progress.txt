## 2026-10-31 - data-01 follow-up: enums instead of strings (requested by user)
- Added resources/game_enums.gd (GameEnums): ClassId, WeaponId, EnemyId, EnemySize, SkillEffect, TargetSide. One shared file so Classes and Weapons need not reference each other.
- Classes.ALL, Weapons.ALL and Enemies.ALL are now keyed by these enums, and all fields that held id strings use them. Use e.g. Classes.ALL[GameEnums.ClassId.FIGHTER]. The earlier data-01 notes that show strings are out of date.
- GameState: hero class_id is a GameEnums.ClassId. to_dict() saves its name ("MAGE") and from_dict() converts it back, so reordering the enum cannot corrupt saves. An unknown name in a save pushes an error and falls back to FIGHTER. Any enum saved later (weapons in equipment, for example) must do the same.
- CLAUDE.md gained an "Ids are enums" rule. The encounters-01 step now uses EnemyId.
- Still strings on purpose: SceneRouter names (few call sites, bad names already give a clear error) and audio ids (they are file names).
- Slots became enums too, at the user's request: GameEnums.HeroSlot (1-3), EnemySlot (4-7), and Slot (1-7), whose values are defined from those two. Values equal the slot numbers. class_slot_skills and abilities are keyed by HeroSlot, target_slots hold Slot values, and make_hero() takes a HeroSlot.
- Saves store slots as numbers, not names. This is a deliberate exception to the enum rule, because slot values are pinned and cannot shift when entries are reordered.
- Skills moved to resources/skills/skills.gd at the user's request: Skills.ALL keyed by GameEnums.SkillId, with the skill shape documented there. Classes, weapons and enemies now hold only SkillIds, so use e.g. Skills.ALL[Classes.ALL[id]["class_skill"]]. Added resources/skills/ to the CLAUDE.md tree. No skill values changed.
- Verified after the skills move: import clean, 347 checks, no failures, including that every reference exists and every skill is used. A before/after diff of all 25 fully resolved skills, with their class, weapon and enemy data, is identical.
- Verified after the slot change: import clean, 302 checks, no failures, including that Slot equals HeroSlot + EnemySlot in names and values, and that slots survive a save and load.

Throwaway script, 294 checks, no failures: every enum entry has data, all skill fields are valid, a save stores "MAGE" and loads back as the enum through real JSON, and an unknown class falls back with an error.
